# 工单中心

本 Fork 的独立客服模块：用户入口 `/tickets`，管理员入口 `/admin/tickets`，页头对话图标显示未读工单数。

## 使用流程

用户填写标题、问题类型、文字或截图后提交。管理员可回复或切换状态；所有状态变化都会记录在对话中。

- 新建或用户回复：待处理。
- 管理员开始处理：处理中。
- 管理员回复：待用户回复。
- 用户或管理员可以标记已解决，之后重新打开才可继续回复。
- 已解决工单重新打开：待处理，并检查未解决数量限制。
- 用户没有删除入口和删除权限，包括自己创建及已解决的工单。仅管理员可在详情中确认永久删除；后台接口和存储层均检查管理员身份。

未读以各账号、各工单的消息位置记录。用户看到客服新回复和状态更新；管理员看到用户新消息。多个管理员各自维护已读位置。页头每 30 秒刷新，对话页每 20 秒刷新；隐藏标签页停止自动请求。打开对话后按实际取得的消息位置确认已读，后续新消息不会被旧的确认操作清除。

## 截图及限制

- 支持选择或粘贴 PNG/JPEG 图片，每条消息最多 3 张，每张原始及处理后图片均不超过 2 MiB。
- 单边最多 8192 像素，总像素最多 1600 万；服务端解码并重新编码，移除元数据及尾部内容。
- 扩展名只接受 `.png/.jpg/.jpeg`，另外独立检查文件魔数、解码格式和尺寸；仅改后缀的 EXE、脚本、SVG、压缩包和损坏图片会被拒绝。不执行上传内容，不调用外部转换程序。
- 重新编码过程中限制输出大小；全局最多同时处理 4 个提交、2 个图片解码任务，限制并发内存占用。
- 每个应用实例内，同一账号同时最多 1 个新建或回复请求，用户和管理员界面共享名额；重复提交返回 429，全局名额已满返回 503。
- 新建和回复的请求体必须在进入提交处理后的 30 秒内完整上传，持续少量发送也不会延长期限；超时返回 408，并释放账号及全局名额。单次请求体最多 7 MiB，其他接口及流式 API 不受此上传期限影响。
- 文字最多 5000 字，标题为 2–120 字。
- 每个账号每小时最多尝试新建 5 次，每分钟最多尝试回复 20 次、修改状态 20 次。失败尝试也计入限流，Redis 故障时暂停提交。
- 管理员删除每分钟最多尝试 20 次。每账号从首次截图上传起的 24 小时窗口内，重新编码后的截图合计最多 32 MiB；跨工单及用户/管理界面共享原子计数，写入失败仍计入额度。
- 每位用户同时最多 5 个未解决工单；创建和重新打开均在数据库锁保护下检查。
- 附件通过已登录接口读取，用户只能访问自己的工单。截图无公开静态地址，页面临时 Blob URL 在离开时释放。
- 附件响应使用固定图片类型及文件名，设置 `nosniff`、`private, no-store`、CSP sandbox 和同源资源策略；不会按原文件名生成可执行路径。
- 工单消息体不写入后台审计正文，操作元信息仍沿用现有审计机制。

## 部署与存储

迁移 `243_custom_support_tickets.sql` 增加四张 `support_*` 表，`244_custom_support_retention.sql` 增加过期清理索引，随后端启动自动执行。重新启动新后端并更新前端即可使用，无需新增外部客服服务。生产环境 Nginx/OpenResty 的请求体限制应至少允许 7 MiB（例如设置 client_max_body_size 8m），否则截图可能在到达应用前被返回 413。

截图以私有二进制存储在 PostgreSQL 的 `support_attachments.data`（BYTEA），随数据库备份，不在服务器文件目录或网站静态目录中，无需图片目录挂载。用户被硬删除时，其工单和截图通过外键级联删除。

## 七天保留与自动清理

- 默认按创建时间保留 **7 天**，所有状态适用，包括未解决工单；回复和修改状态不延长保留时间。页面显示保留规则及具体到期时间。
- 环境变量 `SUPPORT_TICKET_RETENTION_DAYS` 可调整为 1–365 天，留空默认 7；无效值阻止后端正常初始化。Docker 部署时加入应用容器的 `environment` 后重建容器生效。
- 到期后立即从列表、未读计数和未解决额度中排除；详情、附件、回复、状态操作及已读接口均按到期规则检查访问。
- 后端完整初始化后清理一次，此后每 15 分钟扫描。每批最多 100 条、每轮最多 10 批，每批超时 30 秒；大量积压可能需要多轮。多个应用实例通过数据库行锁避免重复处理，关闭程序时先停止清理任务再关闭数据库。
- 管理员手动删除或系统清理时，工单、消息、截图、已读记录均通过外键级联移除，业务界面没有恢复功能。
- **更新并重启新后端后，已有超过保留期的工单也会被清理。** 自动清理仅影响当前数据库；历史数据库备份中的内容随备份保留策略到期，清理不等于立即缩小数据库物理文件。

上传校验是防护的一部分，仍需保持 Go 运行时、数据库及反代组件更新，并控制注册和整体请求流量；单账号额度不能代替多账号滥用防护。

开发验证使用独立临时 PostgreSQL 数据库，不连接业务数据：

```powershell
$env:SUPPORT_TEST_DSN = 'host=127.0.0.1 port=<测试端口> user=<测试用户> dbname=<测试数据库> sslmode=disable'
cd backend
go test ./internal/support -count=1
```

不设置 `SUPPORT_TEST_DSN` 时，数据库集成用例跳过，其余权限、图片与限流测试仍运行。测试账号需要在该隔离数据库中创建和删除临时 schema 的权限。
